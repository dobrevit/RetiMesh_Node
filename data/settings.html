Radio

Announces make this node a visible Reticulum destination (retimesh.node) to every RNS peer — the normal way to be discovered. Beacons are a RetiMesh-only quick probe (hello on boot, replies within seconds); off by default.
Duty cycle. What this field means depends on the region above, because the three do not cap the same thing — the note beside the region selector says which one you are in.
In Europe the sub-band decides how much of each hour the node may transmit for, not preference: 0.1 %, 1 % or 10 % depending on where you land (868.0–868.6 is 1 %, 869.4–869.65 is 10 %). The node applies that allowance less a small safety margin and shows the result on the status page, so leaving this at 0 is usually right; a value here is an optional stricter cap.
In the US band there is no hourly allowance at all. What is capped is how long a single transmission may hold the channel, and the node checks that per packet and warns at boot when the longest frame does not fit. At 2.4 GHz neither applies; power and listen-before-talk govern, and the node already does the latter. In both, this field is a budget of your own choosing rather than one being followed, and the local rules remain yours to know. When a budget is spent, packets wait in the queue instead of being dropped.
GNSS. The receiver gives the node a real clock, which it has no other way to get: without one its idea of time restarts at zero on every reboot. Its health (fix, satellites, UTC) is public on the status API; the coordinates are not, unless you publish them — the status page is reachable by anyone who can join this access point.

Reticulum transport

  

    
The node routes for the mesh like rnsd with enable_transport. Each interface has its own
      mode — the same vocabulary as rnsd: full propagates everything, gateway/boundary limit what crosses
      network edges, access point sends no announces to clients (they use path requests instead, which keeps phones off the
      flood), roaming for mobile links.

    

      

        

      

      

        

      

        

      

        

      

      

        

      

      

      

      

    

    
Announce cap limits how much of each interface's airtime announces may use (rnsd default 2 %). The rate target/grace/penalty
      throttle destinations that announce too often — the same knobs as rnsd's announce_rate_*.

    
The Reticulum store (path table, announce cache, known destinations) lives in one place at a time: the microSD card when one
      has been taken into use, otherwise in internal flash next to this web app. It is moved only with Use this card and Eject under
      SD card below — saving this form cannot move it, because moving it means copying the data, which happens during the restart that follows.
      While the store is on the card it cannot be formatted, and pulling the card without ejecting stops the node learning new paths until it
      reboots.

    
    

  


  
SD card

  

    
Checking…

    

    

      

      

    

    

      

      

    

    

    
Taking a card into use restarts the node and copies the store onto it on the way back up, with nothing else reading or
      writing it, and writes this node's name to the card so no other node will claim it. Ejecting copies the store back to internal flash the
      same way and takes it off the card, which is then free for any node to take — no formatting needed. Only one copy exists at a time. A card
      carrying another node's store is left alone; format it first if you mean to take it.

    
The node uses a single FAT32 volume across the whole card. Cards with other layouts (e.g. a Raspberry Pi image:
      small boot partition + Linux partitions) mount only partially and can be reformatted here. Formatting erases all data on the card.

Backup & provisioning

  

    

      

      

    

    

    
The export contains radio, Wi-Fi (including the password), transport and admin settings — keep it private.
      It never contains the node's identity keys. Importing on another node clones its configuration; the SSID stays automatic unless set.
      Where the Reticulum store lives is not imported. That describes the node the backup came from, not the settings being restored, and moving
      the store means copying it — which is what the SD card actions above do.
